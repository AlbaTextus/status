# AlbaTextus Status

少量服务的独立状态板块与手动事件发布后台。初始服务列表和事件列表均为空，没有演示数据。导航栏复用 Connect，页面延续简洁的白底细边框风格。

## 本地运行

```powershell
cd E:\AlbaTextus\status
npm install
npm run build
npm run start -- --hostname 127.0.0.1 --port 3100
```

- 状态页：`http://127.0.0.1:3100/`
- 管理后台：`http://127.0.0.1:3100/admin`
- 只读状态接口：`/api/status`
- 本服务健康接口：`/healthz`
- 已发布事件详情：`/incidents/<id>`；草稿和不存在的事件返回 404。

## 检测规则

| HTTP 响应 | 显示 |
| --- | --- |
| 200 | 绿色，运行正常 |
| 433 | 黄色，维护中 |
| 其他状态码 | 红色，服务异常 |
| 超时、连接失败、DNS/TLS 错误 | 红色，服务异常 |
| 未检测或检测结果超过 90 秒 | 灰色，等待检测 |

服务名称与地址由管理员填写。地址没有 `/healthz` 时自动补全。只接受 HTTP/HTTPS 地址，不接受 URL 内嵌密码、查询参数和锚点；允许访问用户配置的内网服务。

检测由 Node 服务端完成，不依赖浏览器是否打开。每轮结束后 30 秒开始下一轮，每次请求超时 5 秒，并发上限 4。不跟随重定向，3xx 也按异常处理；只看 HTTP 状态码，不解析响应正文。后台保存服务时立即检测，也支持单项检测与全部检测。前台每 10 秒读取最近检测结果。

## 手动公告与事件

首页保留 System status 历史面板：每个服务一行，状态条使用原来的 90 格表示过去 24 小时，每格代表 16 分钟，不显示延迟。每次健康检测归入对应区间，并以该区间内最严重状态着色（异常优先于维护、维护优先于正常）；无记录为灰色，不补造过去数据。可用率为过去 24 小时 HTTP 200 次数 / 全部实际检测次数，维护计入分母，没有采样的区间不参与计算。记录随服务持久化；更名或修改地址后保留同一服务的记录。

在后台创建事件，自行填写标题、关联服务（可不关联）、事件进度，以及每条更新的状态名称和正文。支持：

- 保存草稿、发布、编辑已发布内容、撤回草稿、删除事件。
- 添加或删除更新记录，预览正文；最新更新排在最上面。
- 将事件标记为已结束，已发布事件仍保留在状态页。
- 更新的时间由服务器记录，编辑已有更新保留其原始时间；显示北京时间。

健康检测不会自动创建事件或修改手写文案。手动事件是否结束也不覆盖 HTTP 检测结果。删除服务后，已写事件保留并解除服务关联。

## 存储与访问

数据自动保存到 `data/status.json`，使用进程内写入队列和原子文件替换。默认无文件即空数据，首次写入时创建目录；重启仍保留。备份整个 `data/` 即可。

可在 `.env.local` 中配置：

```dotenv
STATUS_DATA_DIR=E:/AlbaTextus/status/data
STATUS_ADMIN_TOKEN=替换为自己的长随机管理密钥
```

配置密钥后，后台需填写密钥，保存在当前浏览器会话中。未配置密钥时只允许通过 localhost/127.0.0.1 访问管理接口，默认启动命令仅监听回环地址。若开放远程访问，请设置管理密钥并通过 HTTPS 访问。公开状态接口不会返回检测 URL 或草稿。

当前存储与定时器适合 **一个常驻 Node.js 实例**。不要多进程共享同一 JSON 文件；无常驻进程的 Serverless 环境需要另配持久化数据库和调度器。
